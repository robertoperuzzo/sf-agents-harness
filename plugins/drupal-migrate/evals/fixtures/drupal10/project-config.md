# Migration Project Configuration — drupal10 eval fixture

This file provides project-specific values for the generic `drupal-migrate-*` skills.
It is the fixture copy of `references/project-config.template.md`: the eval scaffold
installs it at `.agents/references/migrate/project-config.md` in the run workspace.

The source is a synthetic database generated by `evals/fixtures/generate.py` from
`evals/fixtures/drupal10/spec.json`. Every value below is documented ground truth in
`evals/fixtures/drupal10/expected.json`; nothing comes from a real site.

---

## Source System Overview

| Property             | Value                                               |
| -------------------- | --------------------------------------------------- |
| Source technology    | `drupal8+` (Drupal 10, database-only delivery)      |
| Topology             | `single-site`                                       |
| Delivery             | `DB-only`                                           |
| DB access method     | read-only fixture runner (`fixture query drupal10`) |
| Source codebase path | not delivered (DB-only)                             |
| Target stack         | Drupal 11                                           |

The source is the fixture site `www.drupal10.example`, a **Drupal 10 single site** with
content in `en` (default) and `it`. Only the database was delivered, imported into a
MariaDB container named `dm-fixture-drupal10`, schema `drupal10`. There is one source
database; its key is `drupal10`. The exact core release is not recoverable from the
database alone: `drupal-migrate-detect-version` reports `drupal8+` and the major is
known from delivery notes as 10.

## Database Connection

The source is a **raw dump imported into a database container** (the "Other CMS / raw
dump" access path of the template). There is no settings file and no site CLI: the
only way to read the source is the read-only runner below, which connects as a
database user that holds `SELECT` only and refuses any statement that is not
`SELECT`, `SHOW`, `DESCRIBE`, `EXPLAIN` or `WITH`.

### Connection details

| Parameter              | Value                                           |
| ---------------------- | ----------------------------------------------- |
| Database key (primary) | `drupal10`                                      |
| Schema name            | `drupal10`                                      |
| Host                   | container `dm-fixture-drupal10` (MariaDB 10.11) |
| Read-only user         | `reader` (`SELECT` only)                        |
| Runner option          | fixture name `drupal10`                         |

### Connection command

Run every query through the fixture runner, one statement per call. The command is on
`PATH` in the eval workspace; outside it, call
`plugins/drupal-migrate/evals/fixtures/bin/fixture` from the `sf-agents-harness` checkout.

```bash
fixture query drupal10 'SELECT 1'
```

Substitute this command wherever a skill shows a site-CLI query example. Use
`DATABASE()` in `INFORMATION_SCHEMA` lookups; the runner already selects the
`drupal10` schema.

### Enabling migration mode (optional)

Start the fixture before any query:

```bash
fixture up drupal10
fixture status
```

`fixture up` is idempotent. `fixture down drupal10` removes the container.

## Migration Patterns (project conventions, optional)

1. Read-only source: every query goes through `fixture query drupal10`; never attempt a
   write, and never reach the container by another path.
2. Revision safety: `node_field_data` holds one row per entity and language, and
   `node_field_revision` one per revision; count with `COUNT(DISTINCT nid)`.
3. Analysis output goes under `doc/Migrate/` in the workspace, as
   `drupal-migrate-analysis-docs` prescribes.
